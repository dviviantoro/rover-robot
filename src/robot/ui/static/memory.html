Memory

Pick models and see what they would cost before applying anything. The board has 7620 MiB, not 8192 — the rest is Tegra carveout and never available. Every figure here comes from the model's own header and the measurements in memory-budget.md: the KV cache is computed from each model's real layer and head geometry, which reproduces the 144 KiB/token measured for Qwen3-4B and correctly gives Gemma-3 its much smaller 26 KiB/token. The fixed runtime overhead was measured on the 4B, so small models are priced conservatively.

Estimated is what a model of that size costs, from the measured fits in memory-budget.md — the only thing available for a model that is not loaded. Measured now is that process's RSS, read from /proc when this arrived, and it refreshes every 3 seconds. Where the two disagree, the measurement is right and the estimate needs revisiting.

Model selection

Changing anything here re-prices immediately and applies nothing. Voices are loaded on demand, so all three count only if all three get used.

Applying writes the config and restarts whatever has to reload.

What is actually loaded

A choice reaches the robot through three layers, and each can lag the next: what is chosen here, what is configured in config/*.env, and what the live process actually has open. The last column is read from the process itself, never from the same file as the middle one — two readings of one file would agree by construction and prove nothing. Same data as python scripts/measure/whats_running.py and the Services page.
